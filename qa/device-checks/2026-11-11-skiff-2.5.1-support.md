# Device check: skiff-2.5.1-support, 2026-11-11

Written by the session that built it (see `CLAUDE.md`, rule 2). Scott runs it with the iPad and the FM-1; the branch merges to `main` only after it passes.

**Setup:** Skiff-Lupe 2.5.1 on the FM-1 (`firmware/releases/Skiff-Lupe-2.5.1.fwsc`, SHA-256 `80b21b33…f71302c`, identity `FM-1_725`) · Lupe from branch `skiff-2.5.1-support` · USB cable, the FM-1's screen in view. Install the two together: this Lupe build first, then the firmware through Lupe's Install firmware (pick **Skiff-Lupe 2.5.1**; in a Debug build Lupe uses the repository's copy, no download).

**Back up first? Yes.** Installing firmware writes the FM-1's flash, and 2.5 moves every FM-1 to CPU 2 CORES on its first boot (settings rev 3). Before installing: Lupe › Projects, save the music to the iPad (keep at least one project made on 2.2 for check 9), and let Install firmware make its own backup. Checks 6, 9 and 10 also write: 6 MENU's settings, 9 opens a project, 10 replaces a track's pattern (one undo).

Screenshots of these screens on the 2.5.1 demo and the 2.2 demo: `qa/skiff-2.5.1-2026-11-11/`.

**Already checked off the device:** against skiff-sim built from the 2.5.1 firmware's own source (737e3fb): SCREEN_GOTO and the button map on every page Lupe uses (`SkiffSongSimTests`, SKIFF_LINK=1), the IDs and DESC, motion ids, step round trips, the mixer, and the song tests, each passing when run alone. Two sim tests fail the same way on a 2.2 sim, so they predate this branch: `songPlaybackRulesOnTheFirmware` (launch timing) and `SkiffProjectSimTests.roundTrip` (an edit not seen in the pool read). On the 2.5.1 sim, tests run back to back sometimes hit an INFO timeout and pass when re-run alone; worth watching on the FM-1 at connect (check 1).
